# customer-extensions/ — per-customer packaging output

This is the **output** side, not a place to hand-edit code. See `docs/CUSTOMER-EXTENSIONS-PLAN.md`
for the full design. If you have existing customer code/material to bring in first, that goes
through `external/incoming/` instead — see `external/README.md`.

## Layout

```
customer-extensions/
  <customer-slug>.config.json   <- you create/edit this by hand (copy TEMPLATE.config.json)
  <customer-slug>/
    manifest.md                 <- you write this: what's included, tenant, notes, history
    build/                      <- generated by the packaging script, gitignored, never edit
    <customer-slug>-*.zip       <- generated, gitignored
```

## To set up a new customer

1. Copy `TEMPLATE.config.json` to `<customer-slug>.config.json` and fill in their tenant,
   target repo URL, and which optional modules (e.g. `erp`) they get.
2. Make sure `environments/<customer-slug>.js` + `settings/<customer-slug>.js` already exist and
   work locally (`npm start <customer-slug>`) — packaging reuses these, it doesn't create them.
3. Create `customer-extensions/<customer-slug>/manifest.md` with a short intake note (see
   `docs/DEVELOPMENT-ENVIRONMENT-PLAN.md`'s intake record shape).
4. Run the packaging script once it exists (`tools/package-customer-extension.js` — not built
   yet, see the plan doc) to produce the ZIP and/or push their repo.

Nothing pushes anywhere without being shown to you and confirmed first, same as everywhere else
in this repo.
